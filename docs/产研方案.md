## 一、产品愿景与版本路线

### 1.1 愿景

以**策略引擎**为核心，建设可扩展的**全球性、多品类、全自动**量化交易能力；数据与执行层抽象统一，便于后续接入更多交易所、资产类别与策略类型（含未来高级策略与 AI 策略）。

### 1.2 切入点与里程碑

- **V0.0.1**：以**加密货币比特币**为业务切入点，在**本地**完成可运行闭环（数据 + 策略 + 交易 + 后台基础能力），对接**币安现货与合约测试网**，经多轮调试优化迭代。
- **V1.0.0**：**真实资金实盘**里程碑（具体风控、密钥与部署规范在临近 V1.0 时另附上线清单）。

### 1.3 V0.0.1 成功标准（验收参考）

- 本地可常驻运行（进程/容器级守护与重启策略可后续完善）。
- 策略引擎可加载、启停、调参；策略侧**不直连交易所 SDK**，订单经统一交易层下发至测试网。
- 后台可查看资产与交易相关核心信息（具体页面以开发排期为准，七模块逐步填满）。
- 无明文密钥入库；敏感配置仅环境变量或本地安全配置。

## 二、系统架构（三大模块与子模块）

系统划分为**数据模块、策略模块、交易模块**，子模块划分如下。

| 大模块 | 子模块 | 职责摘要 |
|--------|--------|----------|
| **数据** | 获取 / 存储 / 处理 | 行情采集（REST/WebSocket 等）、持久化、清洗与特征；预留链上与另类数据扩展 |
| **策略** | 研究 / 回测 / 引擎 | Notebook 或脚本研究；回测与**实盘引擎共享核心逻辑**；运行时调度与状态 |
| **交易** | 实盘（含模拟）/ 风控 / 监控 | 交易所适配、下单撤单、持仓与回报；风控闸门；健康与告警 |

**架构原则（便于后续 Go + Python，避免推倒重来）**

- 策略只产出**订单意图**（品种、方向、数量、市场类型、是否只减仓等），由**交易模块**映射为具体 API 请求。
- 交易所访问集中在 **ExchangeConnector / 适配器**实现中；未来可将该层替换为 **Go 执行服务**，策略仍保持 Python，无需重写全系统。
- V0.0.1 采用 **Python 模块化单体**（或轻量队列解耦），不提前上复杂微服务，以保证迭代速度。

## 三、技术栈（已定）

- **语言与后端框架**：**Python 全栈**（推荐 **FastAPI** + asyncio；行情 WebSocket、任务调度按实现阶段选型）。
- **策略与回测**：与引擎共用同一核心库，保证信号与参数逻辑一致。
- **前端**：易用的后台管理端（如 **React + Ant Design Pro** 或等价方案），与后端 **REST / WebSocket** 对接。
- **后续可选演进**：交易执行层可渐进引入 **Go**（仅替换「对接交易所、发单」实现与部署形态），不以 V0.0.1 为前提。

## 四、数据与存储

| 用途 | 技术选型 | V0.0.1 说明 |
|------|----------|-------------|
| 主库与业务数据 | **PostgreSQL** | 用户、策略配置、订单/成交/持仓同步状态等 |
| 时序行情 | **TimescaleDB**（PostgreSQL 扩展） | K 线、成交等按时间分区查询 |
| 缓存 / 队列 / 锁 | **Redis** | 按需启用：行情缓存、轻量队列、分布式锁等 |
| 链上 / 另类数据 | 同上库表结构 | **仅表结构与空任务（占位调度）**，不接真实外部数据源 |

**部署与数据位置**：V0.0.1 通过 **Docker Compose** 在本机启动数据库与 Redis，数据持久化在**本机 Docker 卷**；应用通过 `localhost` 与 `.env` 中 `DATABASE_URL`、`REDIS_URL` 连接。

**风险**：本机单副本、无异地备份时，硬件故障或误删卷可能导致数据丢失；重要节点建议自行 `pg_dump` 或备份数据卷。

## 五、交易与交易所

- **V0.0.1 范围**：**币安现货测试网**与**合约测试网**均需支持（统一抽象，不同 `MarketType` 与 base URL/接口实现）。
- **接口策略**：API 与策略隔离；**统一封装**；适配器层支持未来**多交易所**扩展（V0.0.1 以实现币安测试网为主）。
- **密钥管理**：API Key / Secret **仅通过环境变量**（如 `.env`，且 **`.gitignore` 忽略 `.env`**）注入运行时；**禁止**写入代码库与方案中的真实密钥；测试网密钥亦同流程管理，避免习惯带到实盘。

---

## 六、策略引擎（V0.0.1）

- **核心地位**：系统以策略引擎为驱动；简单、经典、**可配置参数**的策略优先，便于后台调参与研究。
- **建议内置方向**（实现以开发排期为准）：双均线交叉、RSI 超买超卖、布林带类均值回归（简化版）；网格等可放后续小版本。
- **扩展**：预留策略生命周期与插件式接入，便于后续接入高级策略或外部研究产出。

---

## 七、前端后台管理系统

### 7.1 框架模块（七大块）

1. **资产收益**  
2. **实盘交易**（V0.0.1 对应测试网）  
3. **数据图表**  
4. **策略引擎**  
5. **风控配置**  
6. **系统监控**  
7. **账号管理**

### 7.2 认证与账号规则（已定）

- 支持**登录 / 退出**、**创建账号**、**角色与权限**（RBAC）。
- **初始化超级管理员**：用户名 **`admin`**，初始密码 **`123456`**（仅限本地调试场景；生产或外网暴露环境须改密并强化策略）。
- **后续新建用户**：首次密码为**随机生成**；用户**首次登录强制修改密码**。

## 八、安全与合规（摘要）

- JWT、HTTPS（部署阶段）、CORS 与审计日志（关键操作留痕）随开发迭代补齐。
- 加密资产高波动与合约风险需在风控与仓位上保守配置；本方案为技术实现说明，不构成投资建议。
- 合规与牌照要求由负责人在所在地自行评估。

## 九、开发、测试与本地里程碑

- **测试**：单元测试（指标、风控规则、意图解析）、集成测试（Mock 或测试网）、关键后台流程 E2E（可选）。
- **V0.0.1 里程碑**：**代码 + 数据 + 版本管理（Git）全部在本地**；**本地环境完整跑通**（后端、依赖服务、测试网连通）作为进入后续版本优化的基线。
- **部署上线**：云服务器与生产发布不在 V0.0.1 必达范围；**V1.0.0 实盘**前须另过上线评审与清单。

## 十、版本管理（Git）与协作约定

### 10.1 Git

- **自 V0.0.1 起**：在项目根目录使用**本机 Git**（`git init`），用于历史与回退。
- **至 V1.0.0 前**：不向远程代码托管**推送**；远程仓库可在 **V1.0.0**（或负责人指定节点）再启用。
- `.env`、密钥、虚拟环境目录等必须列入 `.gitignore`。

### 10.2 行动边界（人与 AI 协作）

- **负责人**：开发以外事项（账号、服务器、密钥保管、验收、合规判断等）。
- **开发实现**：由 AI 助手承担主要编码与迭代；**须在负责人明确发出「开始行动 / 开始开发」类指令后**，再执行代码修改、命令执行等开发动作；方案讨论阶段以文档与口头结论为准，不擅自改代码。
